¿Qué es?
  Una API REST (FastAPI) que conecta tu almacén WMS con Dolibarr ERP.

¿Por qué?
  Automatizar recepción, picking e inventario usando datos de Dolibarr
  sin modificar la base de datos de Dolibarr (solo lectura).

¿Cómo?
  
  Dolibarr DB ─── [API WMS] ──→ WMS Local DB
    (lectura)       (FastAPI)     (lectura/escritura)

¿Qué puede hacer?
  ✅ Recibir mercadería con foto      (POST /api/v1/receive)
  ✅ Crear órdenes de picking         (GET /api/v1/orders)
  ✅ Verificar stock en tiempo real    (GET /api/v1/check/{barcode})
  ✅ Crear movimientos en Dolibarr    (automático)
  ✅ Multi-tenant (clientes separados) (por implementar)

🎯 DECISIONES ARQUITECTÓNICAS - POR QUÉ ASÍ
════════════════════════════════════════════════════════════════════════════════

1️⃣ FASTAPI (vs Django, Flask)
   ├─ ✅ Ultra rápido (async/await nativo)
   ├─ ✅ API REST enfocado (tu caso perfecto)
   ├─ ✅ Validación automática (Pydantic)
   ├─ ✅ Documentación Swagger auto
   └─ ✅ Moderno y activamente mantenido

2️⃣ DOS BASES DE DATOS SEPARADAS
   ├─ Dolibarr → LECTURA PURA
   │  ├─ No modificamos Dolibarr
   │  ├─ Es la "fuente de verdad"
   │  └─ Si Dolibarr se actualiza, OK
   │
   └─ WMS → LECTURA/ESCRITURA
      ├─ Datos de operaciones WMS
      ├─ Independiente de Dolibarr
      └─ Puedes hacer rollback

3️⃣ ARQUITECTURA EN CAPAS (Separación responsabilidades)
   ├─ Routers → QUÉ (endpoints HTTP)
   ├─ Services → CÓMO (lógica de negocio)
   ├─ Models → CON QUÉ (estructura datos)
   └─ Database → DÓNDE (conexiones raw)
   
   Beneficio: Si cambias BD, solo modifica 1 archivo

4️⃣ SQLALCHEMY ORM
   ├─ ✅ Type-safe (LlxProduct es objeto, no dict)
   ├─ ✅ Previene SQL Injection (parametrizado)
   ├─ ✅ Portable entre bases de datos
   └─ ✅ Transacciones automáticas

5️⃣ PYDANTIC SCHEMAS
   ├─ ✅ Validación automática (tipos, rangos)
   ├─ ✅ Conversión de tipos (string→int)
   ├─ ✅ Documentación Swagger auto
   └─ ✅ Error messages claros al cliente

✨ RESUMEN: POR QUÉ ESTA ARQUITECTURA FUNCIONA
════════════════════════════════════════════════════════════════════════════════

✅ ESCALABILIDAD
   - Cambiar BD? Edita database.py nada más
   - Agregar endpoint? Copia función, nuevo router
   - Multi-tenant? tenant_id ya en modelos

✅ MANTENIBILIDAD
   - Nueva validación? → models/schemas.py
   - Nueva query? → services/dolibarr_service.py
   - Nuevo endpoint? → routers/nuevo.py
   
✅ TESTABILIDAD
   - Services reciben DB como parámetro
   - Mock DB fácil para tests unitarios
   - No depende de BD real

✅ INDEPENDENCIA DE DOLIBARR
   - Lectura pura (no corrompemos Dolibarr)
   - WMS funciona aunque Dolibarr esté offline
   - Datos WMS están protegidos

✅ SEGURIDAD
   - SQL Injection prevention (ORM)
   - CORS configurado
   - Credenciales en .env (no hard-coded)
   - Dependency injection (sesiones cerradas auto)
